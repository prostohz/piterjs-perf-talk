# Устройство target

Target объединяет исходную библиотеку и обвязку для проверки и измерения производительности её [слепков](pipeline.md#слепки-библиотеки). Подготовка target не включает запуск автономного цикла оптимизации. Все пути ниже указаны относительно корня проекта.

## Структура

Каждая подключённая библиотека представлена каталогом `targets/<имя>`:

```text
targets/
  <имя>/
    target.ts
    source.json
    library/
    harness/
```

- `source.json` — источник библиотеки: URL репозитория и полный SHA исходного коммита.
- `target.ts` — точка входа для пайплайна; экспортирует по умолчанию объект с интерфейсом `Target`.
- `library/` — отдельный Git-репозиторий исследуемой библиотеки, исключённый из Git основного проекта.
- `harness/` — обвязка: тестовое приложение, сценарии, тестовые данные и измерители.
- Агент изменяет слепок библиотеки; обвязка подключает переданный ей слепок.
- Изоляция библиотеки позволяет оформить принятые изменения в коммит и PR разработчикам без включения обвязки.

### Пример source.json

Для Day.js:

```json
{
  "repository": "https://github.com/iamkun/dayjs.git",
  "commit": "436bde0bcded312781cbe45dc2b0ef079a36d8e3"
}
```

`source.json` хранится в Git проекта. Пайплайн использует заранее клонированный `library/`, проверяет, что это отдельный Git-репозиторий с HEAD на указанном коммите, и копирует его отслеживаемые файлы. Незакоммиченные изменения блокируют создание baseline.

## Сценарии

Сценарии заданы в обвязке, отражают типичное использование библиотеки и используют фиксированные тестовые данные. Для каждого определены границы измерения, объём работы, измеряемая операция и проверка корректности результата.

## Интерфейс target

Пайплайн загружает `targets/<target>/target.ts` и передаёт ему путь к проверяемому слепку библиотеки.

```ts
import type { Metric } from "../../src/pipeline/metrics.js";

interface Target {
  scenarios: string[];
  prepare(libraryPath: string): Promise<TargetSession>;
}

interface TargetSession {
  test(): Promise<void>;
  measure(scenario: string, targetMetric: Metric): Promise<Record<string, number>>;
  close(): Promise<void>;
}
```

- `scenarios` — идентификаторы фиксированных сценариев обвязки.
- `prepare` устанавливает зависимости библиотеки и обвязки через `npm ci`, собирает переданный слепок и возвращает сессию. Оба target сверяют lock-файл библиотеки с сохранённой копией `harness/library-package-lock.json`.
- `test` запускает тесты подключённой библиотеки и возвращает ошибку при падении.
- `measure` выполняет один повтор сценария в новом контексте браузера с чистым состоянием и отключённым HTTP-кэшем, без отдельного прогрева операции. Возвращает объект с единственным ключом выбранной метрики. Неподдерживаемая метрика или некорректный результат сценария вызывают ошибку. Текущие targets поддерживают только `operationTimeMs`.
- `close` закрывает браузер и сервер обвязки; пайплайн вызывает его в `finally` после получения сессии.

Пайплайн управляет слепками, агентом, числом повторов, статистикой и сравнением результатов. Подготовка выполняется при вызове `verify_library` и повторно перед замерами. После работы сессии пайплайн восстанавливает исходники слепка, удаляя установленные зависимости и результаты сборки.

Контроль целостности обнаруживает изменение и удаление исходных файлов target и любые изменения исходной библиотеки. Добавление новых файлов в обвязку этой проверкой не контролируется.

## Проверки

Отдельной команды проверки готовности нет. Сборка, тесты и корректность результатов проверяются во время прогона:

- baseline проходит подготовку, тесты и измерения всех сценариев;
- кандидат проходит `verify_library` до измерения производительности;
- пайплайн проверяет наличие только выбранной метрики, конечность и неотрицательность значений, полноту серий и положительность медиан baseline;
- обвязка проверяет результат каждой операции, а пайплайн сохраняет ошибку и останавливает прогон при некорректном результате.

Отдельные отчёты и слепки проверки готовности не создаются.
